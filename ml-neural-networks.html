Artificial neurons and layered networks

A neuron calculates a weighted sum of its inputs, adds a bias and applies an activation function. Arranging these units in layers creates a nonlinear mapping from an input vector to an output vector.

h(ℓ)=φ(ℓ)(W(ℓ)h(ℓ−1)+b(ℓ))

The same operation is repeated through the hidden layers. Early layers transform the original variables, while later layers combine the transformed values into task-specific features.

Forward and backward passes

The layer equation above is applied once per layer to produce a prediction. The animation below shows this forward pass for a small network with three inputs, four hidden units and one output, revealing the weighted sum and activation computed by each unit in turn.

Backpropagation then runs the same network in reverse. Starting from the difference between the predicted output and a target value, the chain rule is applied one unit at a time to recover the gradient of the loss with respect to every weight and bias, matching the training objective introduced below.

Training through loss minimisation

A loss function measures disagreement between the model output and its target. Backpropagation calculates the gradient of the loss with respect to each parameter. A gradient-based optimiser then updates the weights and biases over successive mini-batches.

θ^=arg minθ1n∑i=1nL(f(xi,θ),yi)

Convolutional operators

A convolution applies one learned kernel to successive local windows. Reusing the kernel allows the same temporal pattern to be detected at different positions. A strided convolution reduces the sequence length, while a dilated convolution spreads the kernel taps apart and widens the receptive field without adding kernel parameters.

StrideMoves the kernel by more than one position and downsamples the sequence.
DilationAdds gaps between kernel taps and expands the temporal view.
TransposeIncreases sequence length in the decoder but is not an inverse convolution.

The receptive field of deeper layers grows because each output combines the receptive fields of the preceding layer. The neural-network operators page illustrates these operations with animated examples.

Autoencoders

An autoencoder contains an encoder that maps an observation to a lower-dimensional embedding and a decoder that reconstructs the observation from the embedding. Training minimises reconstruction error, so the bottleneck must retain information required to reproduce the inputs.

z=genc(x),x^=gdec(z)

Autoencoder geometry

This section explains how the decoder shapes distances in the learned representation space, including the pullback metric and decoded paths used in the thesis analysis.

Why latent distance needs checking

An autoencoder contains an encoder f that maps an input to a lower-dimensional code and a decoder g that reconstructs the input from the code. A common downstream workflow treats the codes as ordinary feature vectors and applies clustering with Euclidean distance. This workflow assumes that distances between codes reflect differences between the corresponding reconstructed inputs.

Reconstruction loss does not directly impose that constraint. Similar inputs are not guaranteed to receive nearby codes, and nearby codes are not guaranteed to decode to similar outputs. The decoder can stretch one part of the code space and compress another, so equal Euclidean steps can represent different amounts of input-space change.

The distortion in the second panel is a local property of the decoder rather than a global scale factor, so it cannot be corrected by rescaling or standardising the codes. Measuring it requires the derivative of the decoder with respect to its inputs.

Geometric role of the autoencoder

Varying the latent code traces a reconstructed surface, denoted Mrec, that need not coincide with the true data manifold.

f:Rd →Z g:Z→ Mrec ⊂Rd

Latent codes act as coordinates for the reconstructed surface. Equal steps in those coordinates need not produce equal changes after decoding, even when reconstruction is accurate.

Decoder Jacobian and pullback metric

The decoder Jacobian describes the local response of the reconstructed output to a small change in each latent coordinate. For a decoder from a p-dimensional code space to a d-dimensional input space, the Jacobian at code z is

Jz= ∂g(z) ∂z ∈R d×p

Each column gives the input-space direction produced by a small displacement along one latent axis. The pullback metric combines these directions into a local measure of decoder distortion:

Mz= JzT Jz ∈R p×p

For a small latent displacement, the quadratic form below approximates the corresponding squared change in the decoded input:

ΔzT Mz Δz

A large value means that the decoder turns a small latent step into a large reconstructed change. A small value means that the same latent step produces little reconstructed change. Variation in the metric across the code space therefore describes local stretching and compression by the decoder.

Curvature and coordinate distortion

A flat manifold does not guarantee undistorted latent coordinates: the decoder can still stretch one region and compress another. Intrinsic curvature and coordinate distortion are therefore different properties. Whether Euclidean latent distance approximates decoded distance must be checked for the fitted model.

The pullback metric measures decoder sensitivity rather than predictive uncertainty, and it describes a single fitted decoder rather than a distribution over plausible decoders.

Decoded paths

A simple decoder-induced path places equally spaced points on the straight line between two latent codes, decodes every point and sums the Euclidean distances between consecutive decoded outputs. This procedure measures the length of the decoded straight path, not necessarily the shortest path on the reconstructed manifold.

For a continuous latent curve γ, the Riemannian length equals the arc length of the decoded curve:

L[γ]= ∫01 γ˙tT Mγt γ˙t dt

Geodesics and minimal decoded paths

The geodesic is the path with the smallest length under this metric. In distorted latent coordinates the geodesic is not necessarily a straight line, so the shortest decoded route between two codes cannot be assumed to be the linear interpolation used above.

Discrete geodesic procedure

  1. Place T path points on a linear interpolation between the two fixed latent endpoints.
  2. Treat the interior path points as optimisation variables while keeping the endpoints fixed.
  3. Decode every path point using the trained decoder.
  4. Calculate the sum of squared distances between consecutive decoded outputs.
  5. Backpropagate through the decoder and update the interior path points.
  6. Repeat until the relative change in path energy is below the convergence tolerance or the iteration limit is reached.

The discrete decoded-path energy is

E[γ]= ∑i=0 T−2 ‖g(zi+1) −g(zi)‖ 2

Use in the thesis

The 9,364 distinct training embeddings produced more than 43 million unique pairs, so a complete Riemannian distance matrix was not constructed and the full dataset was not reclustered under that metric.

The main diagnostic used nearest-neighbour graph edges. Each straight latent path was divided into ten segments. The 11 decoded outputs were flattened across all six channels and time steps, and the consecutive decoded distances were summed. These path lengths were correlated with Euclidean distances in the standardised embedding.

For 1,200 sampled pairs spanning the Euclidean distance range, the interior path points were also optimised from a linear initialisation. This checked whether the straight-path conclusion remained valid when the decoded path energy was minimised.

Pairwise Riemannian distances can be used directly by methods that accept arbitrary dissimilarities, including hierarchical clustering and graph-based analyses. Standard K-means requires coordinates and cannot accept an arbitrary distance matrix without a separate Riemannian formulation.
