Representation learning

Representation learning transforms observations into features for later analysis. The aim is not simply to use fewer features, but to organise information in a form suited to the task.

This page accompanies the Autoencoders subsection of the Machine learning algorithms and related methods section of the thesis. It provides additional background on invariance, disentanglement and shared representations.

Purpose of a representation

The performance of a machine-learning method depends on the representation supplied to it. Let X denote an input space containing observations such as feature vectors, time series or images. A feature transformation maps an observation x to a representation z in a feature space Z.

z=φ(x),x∈𝒳,z∈𝒵

The transformation can be designed manually through feature engineering or learned from the observations. A transformation learned from data is referred to as representation learning or feature learning [2].

Representation learning is often associated with dimensionality reduction, but fewer dimensions are not required. A learned representation can contain fewer, the same number of or more dimensions than the input. The undercomplete autoencoder in the thesis deliberately produces a lower-dimensional representation.

A representation is useful when the representation makes a subsequent task easier. A compact feature vector is not necessarily suitable for prediction or clustering, because a downstream algorithm can use only the information that the representation encodes.

The figure below shows the same observations under two representations. In the input coordinates the two classes form a ring and a surrounding band, so no straight boundary separates the classes. A nonlinear representation of the same input data places the two classes on either side of one straight line. The representation therefore vastly simplifies the classification task, because the problem becomes linear.

Invariant features

Invariance is one goal of representation learning. A representation is invariant to a specified transformation when the feature values do not change under that transformation, so the same feature is extracted from every input that the transformation relates. In practice, a model reduces the sensitivity of the representation to the transformation rather than eliminating the sensitivity. For object identification in an image, the aim is a representation that is invariant to differences in lighting and rotation between images, because the identity of the object does not change when the lighting or the orientation changes [1].

Environmental regionalisation does not have one response variable that determines which variation is irrelevant. Temperature, precipitation, humidity, wind and their temporal patterns all distinguish locations, so no environmental channel is discarded as a nuisance factor. The autoencoder was therefore trained with a reconstruction loss, because the reconstruction objective retains the variation required to reconstruct the input. The clustering step then forms regions from the latent representation produced by the reconstruction objective.

Disentanglement

Disentanglement aims to represent different factors of variation separately. An object representation could separate identity, orientation and lighting, while a video representation could separate identity, movement and camera position. Unlike invariance, which suppresses sensitivity to a selected factor, disentanglement aims to keep factors separately accessible for different tasks [1].

Disentanglement is a common objective in image analysis, because separate factors can be inspected individually and reused for other tasks [1]. The autoencoder in the thesis had no disentanglement objective, because unsupervised training provides no signal that identifies which environmental factor each embedding dimension should represent [3]. Information about one environmental factor could consequently be distributed across several embedding dimensions.

Reusing and sharing representations

A representation learned in one setting may contain features useful in another. Transfer learning reuses learned information for another setting or task, either by keeping an encoder fixed or by fine-tuning its parameters. Domain adaptation addresses changes in the input distribution for a related task [1].

  • Multitask learning: several tasks use shared features while retaining task-specific outputs.
  • Multimodal learning: separate encoders process different input types, and learning connects their representations.
  • Transfer learning: a previously learned representation provides a starting point for a new application.

Reuse is most promising when tasks or domains share relevant factors. Useful transfer is not automatic, so performance must be evaluated on the new task or domain [1].
